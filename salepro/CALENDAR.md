# ปฏิทินคิวงาน

เปิดจาก Overview → ปฏิทินคิวงาน ใช้ข้อมูลเดิม ไม่สร้างรายการนัดหรือส่งข้อความแจ้งเตือนเอง

- ติดตั้ง/งานช่าง: `DealStatus.techJobs[].scheduledAt` พร้อมชื่อช่างและเวลาเริ่ม
- นัดรับชำระ: `PaymentDueDate` หรือ `DealStatus.paymentDueDate` เฉพาะยอดยังค้าง
- หมดอายุ: `DealStatus.expiries[].expiryDate` ที่ยังไม่ต่ออายุ และวันสิ้นสุดสัญญา `Contracts.Value.end`
- PM/MA: `Contracts.Value.serviceAgreement.visits[].plannedDate` ไม่สร้างวันจากเดือนที่ยังไม่กำหนดวันนัด

Settings `DealStatus_<quoteId>` มีลำดับเหนือ DealStatus ในใบเสนอราคา ปฏิทินโหลดด้วย read API เท่านั้น ไม่เรียก migration/ensureContractNumbers แสดงใบเสนอราคาตาม `filterQuotesForUser` เดิม สัญญาที่เชื่อมใบเสนอราคาจะแสดงเมื่อมีใบที่ผู้ใช้มองเห็นและไม่ถูกยกเลิก สัญญาไม่ผูกใบเสนอราคาอ่านตามสิทธิ์หน้าสัญญาเดิม

ไม่นำใบเสนอราคายกเลิก งาน/รอบบริการยกเลิก และรายการชำระครบมาลงคิว งานเสร็จแล้วซ่อนไว้โดยค่าเริ่มต้นและไม่เพิ่มภาระหน้างาน วันไม่ถูกต้องหรือยังไม่ระบุแสดงจำนวนเตือนแยก ไม่สร้างวันนัดแทน

จำนวนและเกณฑ์งานต่อวันอิงตัวกรองที่เลือก นับหนึ่งรายการนัดเป็นหนึ่งงาน ไม่ใช่จำนวนช่างหรือชั่วโมงที่ว่าง เกณฑ์เป็นตัวช่วยดูในหน้านี้ ไม่ใช่กฎห้ามจองคิว เวลาใช้ Asia/Bangkok เตือนนัดเริ่มตรงกันเมื่อช่างคนเดียวกันมีวันและเวลาเริ่มตรงกันเท่านั้น ยังไม่มีข้อมูลเวลาจบสำหรับตรวจงานซ้อนทั้งช่วง

กดรายการต้นทางเพื่อแก้ไขวันนัดในฟอร์มเดิม เมื่อปิดฟอร์มต้นทาง ปฏิทินโหลดใหม่ ขณะโหลดคงรายการที่โหลดสำเร็จไว้เพื่อไม่ให้คิวกระพริบหาย หากโหลดไม่ครบจะแสดงว่าข้อมูลเดิมยังไม่ได้อัปเดต เมื่อบัญชีเปลี่ยนจะล้างข้อมูลของบัญชีเดิมก่อนโหลด
