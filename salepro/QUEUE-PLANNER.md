# นัดหมายจากใบเสนอราคาและจัดคิวรายวัน

## ใช้งาน

1. หน้าใบเสนอราคา มีปุ่ม **▦ นัดหมาย** ในแต่ละใบ สำหรับ Admin และ Sale เจ้าของใบที่ไม่ยกเลิก
2. ระบุวันเวลา ที่อยู่หน้างานจริง และรายละเอียด บันทึกแล้วเป็น **นัดยืนยัน** ทันที ไม่ส่งอีเมล ไม่เปลี่ยนสถานะอนุมัติ/ชำระเงินของใบเสนอราคา
3. ระบุทีม/ช่างได้ หรือเว้นว่างหากยังไม่จัดทีม ระยะเวลาหน้างานไม่ทราบให้เว้นว่าง AI ต้องแจ้งข้อจำกัด ห้ามใช้ศูนย์แทน
4. บันทึกแล้วเปิดวันที่นัดในปฏิทิน และเริ่มวิเคราะห์ให้อัตโนมัติ
5. ในการ์ดนัด กด **เลื่อน / แก้ไขนัด** เพื่อแก้เวลา ที่อยู่ ทีม หรือยกเลิก แก้แถวเดิม ไม่เพิ่มนัดใหม่
6. ปรับเวลาเริ่มออกเดินทาง/จบวัน/เวลาเผื่อในแผงวิเคราะห์ได้ แล้วกดวิเคราะห์ใหม่ ช่วงเริ่มต้นแสดง 08:00–18:00 และเวลาเผื่อ 0 นาที เป็นค่าที่ผู้ใช้แก้ไขได้ ไม่ได้อ้างว่าเป็นเวลาทำงานจริงของบริษัท

## ข้อมูลและสิทธิ์

- นัดใหม่เก็บใน Settings แถวละนัด ชื่อ QueueAppointment_v1_<UUID> ไม่เขียนทับ DealStatus หรืองานช่างเดิม ไม่เพิ่มคอลัมน์ฐานข้อมูล
- ผูก quoteId; ปฏิทินรวมทั้งนัดใหม่ งานช่างเดิม PM/MA และกำหนดอื่นเดิม
- ใช้ filterQuotesForUser และ canManageSaleActions เดิม Sale จัดนัดใบตนเอง Admin จัดทุกใบ Approver ที่ไม่ใช่เจ้าของดูได้ตามสิทธิ์เดิม
- ยืนยันนัดในปฏิทินไม่ใช่มอบหมายเข้า Tech Portal อัตโนมัติ ทีมในช่องนี้ใช้แบ่งกลุ่มเส้นทาง ไม่ได้เพิ่มสิทธิ์หรือส่งข้อความให้ช่าง
- การมอบหมายช่างจริงยังใช้ขั้นตอนเดิม เมื่อมอบหมายงานเดียวกันต้องตรวจไม่ให้เกิดคิวสองรายการ ปัจจุบันยังไม่มีการจับคู่/แปลงนัดไปเป็น techJob อัตโนมัติ
- อ่านค่าล่าสุดก่อนแก้และเช็ก Value เดิมเพื่อกันหน้าต่างเก่าทับข้อมูลที่เปลี่ยนไปแล้ว เป็น optimistic check ฝั่ง client ไม่ใช่ transaction/CAS ฝั่งเซิร์ฟเวอร์ จึงยังมีโอกาสชนกันถ้าบันทึกพร้อมกันในจังหวะเดียวกัน
- key คำขอสร้างคงเดิมตลอดหน้าต่าง เพื่อป้องกันกดส่งใหม่แล้วสร้างซ้ำเมื่อเซิร์ฟเวอร์บันทึกไปแล้วแต่ client ไม่ได้รับผล
- ถ้าบันทึกสำเร็จแต่ AI ล้มเหลว นัดยังคงอยู่ แจ้งสถานะแยกและกดวิเคราะห์ใหม่ได้ ไม่ส่งบันทึกซ้ำ
- ยกเลิกนัดเป็น status cancelled เก็บประวัติไว้ แถวใบเสนอราคาไม่เปลี่ยน

## การวิเคราะห์

- Worker action queueAnalyze ตรวจ Google ID token/allowlist/Origin แบบเดิมก่อนเรียก API
- จุดเริ่มมาจาก Admin > ค่าเดินทาง > จุดเริ่มเดินทาง ต้องตรวจว่าเป็นจุดออกเดินทางจริงของทีม
- รวมงานติดตั้งและรอบ PM/MA ที่มีวันที่ในวันนั้น เฉพาะข้อมูลที่ผู้ใช้มองเห็น ไม่ใช่การรับรองคิวทั้งบริษัท
- แบ่งตามทีม เรียงตามเวลานัดจริง คำนวณ Google Routes จากต้นทางไปงานแรก และจากงานก่อนหน้าไปงานถัดไป ไม่ใช้ระยะจากสำนักงานแทนทุกช่วง
- ใช้ routes.duration + routes.distanceMeters, TRAFFIC_UNAWARE ไม่รวมจราจรจริง และไม่คำนวณกลับต้นทาง
- งานไม่ระบุทีมเป็นกลุ่มสมมติฐาน unassigned ไม่ใช่ทีมที่จัดแล้ว; งานไม่ระบุเวลาหรือระยะเวลาทำงานต้องแสดงข้อจำกัด
- สถานะ possible/unknown/tight คำนวณจากตัวเลขที่ทราบ AI ช่วยสรุป ไม่แก้เวลา ไม่ยืนยันความปลอดภัย/ความตรงเวลาจริง
- Google ได้รับที่อยู่เพื่อหาเส้นทางตามฟีเจอร์ OpenAI ได้เฉพาะรหัส job/team แบบนิรนาม เวลา ระยะทางและระยะเวลา ไม่ส่งชื่อ ที่อยู่ เบอร์โทร หรือข้อความนัดไป OpenAI ใช้ store:false และ Structured Outputs
- สูงสุด 12 นัดต่อครั้ง Google สูงสุด 12 route requests ต่อการวิเคราะห์ และ OpenAI 1 request มีค่าใช้บริการตามบัญชีผู้ใช้ ไม่เรียกซ้ำจากการเปลี่ยนตัวกรอง/เปิดเดือนเฉย ๆ
- ใหม่/แก้ไข/ยกเลิกนัดเริ่มวิเคราะห์อัตโนมัติ หลังบันทึกสำเร็จ ผลเก่าจะถูกล้างเมื่อข้อมูลคิวเปลี่ยน ไม่ใช้ผลล่าช้ามาทับวันที่/บัญชีใหม่
- ต้อง Deploy Worker ใหม่ก่อน AI ใช้งานจริง ถ้าใช้ Worker เดิมอาจแจ้ง unknown action นัดหมายยังบันทึกได้

## Deployment

หน้า SalePro เผยแพร่ผ่าน GitHub Pages ส่วน Worker ผู้ใช้เลือก Deploy เองจากไฟล์ outputs/travel-api/worker-calendar-queue-20261105.js โดยใช้ Secrets/Variables เดิมทั้งหมด

ไฟล์รวมต่อจาก worker-ai-route-20261103.js ที่มีระบบเดิมครบ มี assertion ว่าส่วนเดิมไม่เปลี่ยน ยกเว้นเพิ่ม dispatch ของ action queueAnalyze และ helper ใหม่ หาก Worker จริงมีการแก้อื่นหลังเวอร์ชันนี้ ให้เทียบหรือ merge ก่อนแทนทั้งไฟล์

ทดสอบ Node: queue-core, queue-analysis, work-calendar, gateway-auth, ai-route-plan, travel-routes และ browser mock สร้างนัด เลื่อนวันโดยไม่เพิ่มแถว คง DealStatus เดิม กันหน้าต่างเก่าทับ การวิเคราะห์ล้มเหลว และยกเลิกนัด ไม่มีการเขียนข้อมูลจริง ส่งอีเมล หรือเรียก API เสียเงินจริงในการทดสอบ

เอกสาร: https://developers.google.com/maps/documentation/routes/compute_route_directions และ https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses
