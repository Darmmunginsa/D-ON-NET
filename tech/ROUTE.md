# Route — งานวันนี้

Tech Portal → Route · งานวันนี้ แสดงการ์ดเฉพาะงานของบัญชีที่ล็อกอิน มี scheduledAt ตรงกับวันนี้ใน Asia/Bangkok และยังไม่ completed/cancelled ไม่แสดงงานจากใบเสนอราคายกเลิก

1. ระบุจุดเริ่ม หรือกดใช้ตำแหน่งปัจจุบัน (ขอสิทธิ์เฉพาะเมื่อผู้ใช้กด ไม่ติดตามต่อเนื่อง และไม่เก็บ GPS ลงฐานข้อมูล)
2. ตรวจตำแหน่งหน้างานแต่ละการ์ด แผนที่ pin มีลำดับเหนือที่อยู่ลูกค้า ซึ่งอาจเป็นที่อยู่ออกบิล ลิงก์สั้นและตำแหน่งกลางแผนที่ `@lat,lng` ไม่ถูกเดาเป็นพิกัดหน้างาน
3. เลือกระยะตรง (พิกัดทั้งสองจุด, Haversine, ไม่เรียก API) หรือระยะขับรถ (Google Routes ผ่าน GatewayClient)
4. ยืนยันแล้วกดคำนวณ ระยะเรียงจากจุดเริ่มเดียวกัน ไม่ใช่ greedy route จากจุดก่อนหน้าและไม่ใช่ global route optimization งานที่คำนวณไม่ได้อยู่ท้ายและไม่มีอันดับ ไม่สลับหรือเปลี่ยนเวลานัดจริง

Google Maps ใช้ action travelDistance ที่มีอยู่ ทีละงาน สูงสุด 30 งานต่อรอบ เรียกเฉพาะตอนผู้ใช้กด ไม่มีการเรียก AI และไม่เพิ่ม API key ในหน้าเว็บ ผลคำนวณเก็บเฉพาะหน่วยความจำ เปลี่ยนจุดเริ่ม วิธีคำนวณ สถานะ/นัด/ตำแหน่งงานแล้วล้างผลเก่า ค่าตำแหน่งที่แก้บนการ์ดใช้สำหรับจัดเส้นทางครั้งนี้ ไม่เขียนทับใบงาน

## Backend

การคำนวณขับรถจากพิกัดต้อง Deploy Worker รุ่นที่แปลงสตริง `lat,lng` เป็น `location.latLng` ตาม Routes API ก่อน (รุ่นก่อนส่งทุกค่าเป็น address ซึ่งไม่รองรับพิกัดโดยตรง) รับที่อยู่เดิมได้ตามปกติ ใช้ Secret GOOGLE_MAPS_API_KEY เดิม ไม่มีการเปลี่ยนสิทธิ์หรือ binding

ไฟล์ส่งมอบใน workspace: outputs/travel-api/worker-route-20261103.js รวมกับ Worker จริงที่ผู้ใช้เคยส่งมา รักษา auth, Apps Script proxy และ warranty route เดิมไว้ เครื่องนี้ยังไม่มีสิทธิ์ CLI เพื่อ Deploy Cloudflare จึงต้องให้ผู้ใช้ Deploy ไฟล์นี้ โหมดระยะตรงใช้งานได้โดยไม่ต้องอัปเดต Worker

## ตรวจสอบ

## AI ช่วยจัดแผนวันนี้

คำนวณระยะทางก่อน แล้วเลือกความเร่งด่วน/นาทีทำงานต่อการ์ด (เว้นว่างหากไม่ทราบ) จากนั้นกด AI ช่วยจัดแผนวันนี้ การวิเคราะห์รับได้ 1–20 งาน คืนเป็นแผนแนะนำแยกจากการ์ดลำดับระยะทาง ไม่บันทึกหรือย้ายวันนัดจริง

Frontend ส่งเฉพาะ id ชั่วคราว job1–job20, appointment HH:mm, distanceKm/null, priority normal/urgent, durationMinutes/null และชนิดระยะ ไม่ส่งชื่อลูกค้า เลขใบเสนอราคา เบอร์โทร ที่อยู่ พิกัด หรือข้อความจากใบงาน Worker คัดเฉพาะฟิลด์เหล่านี้อีกครั้งก่อนเรียก OpenAI Responses API ด้วย store:false, strict JSON schema และจำกัด max_output_tokens

Worker ใช้ Secret OPENAI_API_KEY และโมเดลค่าเริ่มต้น gpt-4.1-mini เปลี่ยนได้ทางตัวแปร OPENAI_ROUTE_MODEL ฝั่งเซิร์ฟเวอร์ ต้องเป็นโมเดลที่รองรับ Responses และ Structured Outputs ไม่มีการเรียกจากเบราว์เซอร์โดยตรง ไม่มี API key ในซอร์สหรือหน้าเว็บ

ตรวจผลลัพธ์ว่ามีงานครบทุก id ครั้งเดียว ไม่เพิ่มงาน ไม่เรียงเวลานัดที่ทราบย้อนหลัง และคืนคำตอบที่สมบูรณ์ หากตรวจไม่ผ่านหรือ API ล้มเหลว แสดงข้อผิดพลาดโดยไม่เปลี่ยนข้อมูลงาน ไม่อ้างเวลาถึง/การจราจร/เส้นทางสั้นที่สุด เพราะยังไม่มีข้อมูลระหว่างแต่ละจุด การแก้ตำแหน่ง/ระยะ/รายละเอียดวางแผนจะล้างข้อเสนอเก่าและทิ้งคำตอบที่มาช้า

ไฟล์รวมสำหรับ Deploy: outputs/travel-api/worker-ai-route-20261103.js เพิ่ม action aiRoutePlan และ helper บน Worker รุ่นรองรับพิกัดที่ผู้ใช้ Deploy แล้ว โดยตรวจว่าโค้ดเดิมส่วนอื่นไม่เปลี่ยน ใช้ Secrets เดิมทั้งหมด เครื่องนี้ยังไม่มีสิทธิ์ Deploy Cloudflare จึงต้องให้ผู้ใช้นำไฟล์ที่รวมแล้วไป Deploy ก่อนใช้งานจริง

เอกสาร: [Responses Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)
